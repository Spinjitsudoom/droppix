# droppix v0.4.0 — every desktop, every distro
Turn an Android tablet, a second Linux PC, or any browser into an extended monitor for a Linux desktop.

The first release meant for general use. Until now droppix was really a KDE Plasma app: on other desktops the extra screen might appear, but touch was switched off. The AppImage also only started on distros as new as the machine that built it. Both are fixed. Every desktop below was set up in a virtual machine and driven by a scripted tablet that taps, right-clicks, draws and rotates. Every input was checked to land on the right pixel.

## Desktops

| Desktop | Support |
|---|---|
| **KDE Plasma 6** | ✅ |
| **KDE Plasma 5.27** (Kubuntu 24.04 LTS, Debian 12) | ✅ newly working: touch never worked before (three separate causes) |
| **GNOME** on Wayland (Ubuntu, Fedora Workstation, Debian, Zorin…) | ✅ new |
| **Sway** | ✅ new; start Sway with `WLR_EVDI_RENDER_DEVICE=/dev/dri/renderD128` (see README) |
| **Hyprland** 0.42 or newer | ✅ new, no setup (older Hyprland can't drive the screen at all) |
| **COSMIC** (Pop!_OS, Fedora COSMIC) | ✅ new, no setup |
| **X11** (Cinnamon, Xfce, MATE, GNOME on X11) | ✅ the stylus now works there too |

droppix works out which desktop it's on by itself. It also no longer gets fooled by a leftover socket from an earlier Wayland session, or by KDE tools installed on a GNOME or Xfce machine.

## Packages that run on your distro

The AppImages are now built on Ubuntu 22.04 and run on **any distro with glibc 2.35 or newer**: Ubuntu 22.04+, Debian 12+, and current Fedora, Arch and openSUSE. They use your system's Qt 6 when it has one, and bring their own when it doesn't (stock GNOME or Sway installs). The previous AppImage needed glibc 2.43 and Qt 6.11, so it only started on the very newest Fedora and Arch. The Flatpak's background service gets the same treatment.

You still need the `evdi` kernel module from your distro (or DKMS). See the README for details.

## Fixed

- **The stylus never reached any desktop.** libinput, which every major Linux desktop uses, silently ignored droppix's pen device for missing two capabilities. It now draws on every desktop listed above.
- **Right-click** landed 100 px short on Plasma 6 the first time after you'd used your mouse. KDE's sticky edge between screens was braking the jump. It could also turn into a right-drag when tapped twice quickly. Both fixed.
- **Orientation at connect.** A tablet already held in portrait (or lying flat, or rotation-locked) told the PC it was landscape. It now reports how its screen is actually turned.
- **A tablet that dropped off Wi-Fi** held its session, and blocked its own reconnect, for minutes. It's now noticed within about 10 seconds.
- **Changing the droppix screen's resolution mid-stream** could garble the picture or crash the streamer.
- **Background helpers** (network announcement, streamer) outlived a closed or killed app.
- **The tablet's menu icons** drew as empty boxes on Android 5.
- **USB tethering** no longer lists Wi-Fi tablets as USB, and AOA works without USB debugging.

## Removed

**Mirror mode.** droppix always extends your desktop.
